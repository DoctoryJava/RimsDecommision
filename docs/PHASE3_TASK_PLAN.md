## 1. 文档说明

### 1.1 目的

将 `task.csv` 中 **Phase3：AI智能化赋能** 的 24 项需求转化为可执行计划。Phase3 在 Phase1（基础归档）与 Phase2（能力优化/冷数据）之上，引入 **AI 能力**，实现“自动解析→智能分类/标签→关联挖掘→质量/风险智能识别→语义检索/问答/推荐→智能报表”，将 RIMS 从“可查”升级为“智能可懂”。

### 1.2 术语

| 术语 | 说明 |
|------|------|
| OCR/版式解析 | 从 PDF/Word/图片中提取文本/表格/图表 |
| 实体抽取 | 识别产品/项目/批次/日期/金额等业务实体 |
| 语义标签 | 基于内容语义自动生成标签 |
| 关联挖掘 | 发现记录-对象-事件潜在关联 |
| 语义检索 | 理解意图，返回语义相关而非字面匹配 |
| RAG | 检索增强生成，用于自然语言问答 |
| 敏感信息识别 | 自动识别 PII/PHI/商业机密 |

### 1.3 基线统计

```text
Phase3 24 项分布：
  模块 2 实时数据接入与常态化数据治理 10 项 (41.7%)
  模块 6 合规管控、审计追踪与合规报表  9 项 (37.5%)
  模块 5 档案检索、智能发现与业务利用  5 项 (20.8%)
```

> 明细见 `docs/phase3_tasks.csv`。

## 2. Phase3 整体目标与价值

### 2.1 一句话目标

> **让海量归档数据“自己会说话”：AI 自动完成内容解析、分类打标、关联与质量诊断，用户用自然语言即可精准找到、看懂并利用归档，合规风险与报表也能智能预警与生成。**

### 2.2 演进

| Phase2 已具备 | Phase3 新增价值 |
|---------------|-----------------|
| 人工/规则标签 | AI 语义标签、自动分类，减少 70% 人工 |
| 关键词/全文 | 语义/模糊/同义词/拼音 + 关联推荐 + 智能排序 |
| 固定报表 | 自然语言生成报表 + 台账自动生成 + 趋势智能分析 |
| 人工合规检查 | AI 异常识别 + 敏感识别 + 风险预警 + 智能提醒 |

### 2.3 成功度量

| 指标 | 目标 |
|------|------|
| 文档解析准确率 | ≥92% (文本/表格) |
| 自动分类准确率 | ≥90% |
| 语义检索 NDCG@10 | ≥0.85 |
| 重复数据识别准确率 | ≥95% |
| 合规风险预警召回 | ≥90% |
| 智能报表生成可用率 | ≥95% |

## 5. 技术实现映射

| 能力 | 技术选型（建议） | 集成点 | 说明 |
|------|------------------|--------|------|
| 文档解析 | Azure Document Intelligence / PaddleOCR + 版式模型 | `data_sync_notebook` 增强 | 文本/表格/图表 → 结构化 JSON |
| 实体抽取 | LLM NER + 正则 | 同上 | 产品/批次/日期/金额 |
| 自动分类/标签 | Embedding + 分类器 | `tag_service` 增强 | 预定义分类体系 |
| 重复/关联/异常 | 向量相似度 + 图挖掘 | `quality_service` | |
| 语义检索/模糊 | 向量检索 + 同义词/拼音 | `DynamicQueryBuilder` + 向量库 | |
| 推荐/排序 | 协同 + 内容相关性 | 检索服务 | |
| 问答 | RAG (检索→LLM 生成) | `archive-query` | 需审计 |
| 合规风险/敏感识别 | 规则 + LLM | `compliance_service` | |
| 智能报表 | LLM Text-to-SQL + 模板 | `report_service` | 自然语言→报表 |

**红线保持**：AI 结果均需人工校验/确认方可生效；敏感识别结果仅作标记，不自动脱敏。
