◎AKS 高可用整改总表（按优先级 P0→P3）

核心认知：AKS 只提供基础设施高可用，不提供应用高可用。应用高可用 = 冗余（活副本）× 流量正确性（不打给将死 Pod）× 调度可行性（被赶走的 Pod 有地方去）。业务中断 = Pod 被驱逐 + 没有冗余承接。P0+P1 完成即覆盖 90% 的实际风险。

优先级 整改项 期望配置（要点） 作用 / 不配的后果 验收标准
P0 · 立即执行 纯 PDB 改动，不触碰业务 Pod、不重启、不影响运行中流量
P0 ① PDB 统一用 maxUnavailable
禁 minAvailable + HPA 组合		 
maxUnavailable: 1
unhealthyPodEvictionPolicy: AlwaysAllow
selector:
  matchLabels: { app: <svc> }
HPA 波动大用 "25%"（向上取整）
❌ minAvailable 绝对值 + HPA 缩容 → disruptionsAllowed=0		 防止维护期一次驱逐全部 Pod。
不配：被一次驱逐 / 配错则节点升级永久卡死		 PDB 全用 maxUnavailable；disruptionsAllowed ≥ 1
P0 ② 消除 disruptionsAllowed==0 稳态 ALLOWED ≥ 1；用一条命令排查：kubectl get pdb -A ALLOWED=0 会 drain 永久阻塞，升级超时失败。现象误导：Pod 全 Running、健康全绿但升级失败 全集群 PDB ALLOWED ≥ 1
P0 ③ PDB selector 命中 / 单副本 / 重叠 selector 必须与 Pod 标签完全一致；单副本不配 PDB；禁止多 PDB 命中同组 Pod 不命中 = 保护形同虚设；单副本+PDB = 锁死驱逐；多 PDB = Eviction 直接失败 currentHealthy == 实际副本数
P1 · 核心必改（不改就升级掉请求 · 随下次发版全量带上）
P1 ④ 优雅下线
preStop + terminationGracePeriod		 
terminationGracePeriodSeconds: 45
lifecycle:
  preStop:
    exec: { command: ["/bin/sh","-c","sleep 15"] }
AGIC 场景 15~30s；应用处理 SIGTERM		 SIGTERM 与摘流并行无顺序；preStop 等摘除传播。不配：升级/发版必现 502 对外服务均有 preStop，drain 演练无 502
P1 ⑤ resources.requests 全量 
requests: { cpu: 200m, memory: 512Mi }
limits:   { cpu: 1000m, memory: 512Mi }
memory.limits == requests		 调度地基：驱逐后 Pod 才有落点；QoS 决定驱逐顺序。不配：驱逐后 Pending、HPA 指标失真 所有容器有 requests
P1 ⑥ replicas ≥ 2（核心≥3） 对外 ≥2；核心 ≥3；有状态 ≥3（奇数）
用 kubectl get pod -o wide 验证实际分散		 单副本 = 升级必然中断；同节点多副本 = 假冗余（CA072 实证） replicas 达标且实际跨节点
P1 ⑦ readinessProbe 规范 
readinessProbe:
  httpGet: { path: /health/ready, port: 8080 }
  periodSeconds: 5
  failureThreshold: 3
端点真实反映能否处理请求		 防止未就绪切入流量。不配：请求打到未就绪 Pod readiness 已配置且真实
P1 ⑧ liveness 禁查外部依赖 liveness 只查进程自身；❌ 不查 DB/Redis/下游 查外部依赖 → 依赖抖动 → 全副本重启 → 级联雪崩 liveness 不查外部依赖
P2 · 生产标准（1~2 个迭代内补齐）
P2 ⑨ topologySpread 分布约束 
topologySpreadConstraints:
  - maxSkew: 1
    topologyKey: kubernetes.io/hostname
    whenUnsatisfiable: ScheduleAnyway
核心服务用 DoNotSchedule；AZ 集群加 zone 级		 结果约束，Pod 均匀分布；preferred 反亲和会被稀释（CA072） spread 已配置，Pod 实际分散
P2 ⑩ 发版策略 maxUnavailable:0 
rollingUpdate:
  maxUnavailable: 0
  maxSurge: 1
minReadySeconds: 10
 发版先起新再停旧，零容量损失；PDB 对发版不生效，由 rollingUpdate 管 对外服务 rollingUpdate=0
P2 ⑪ HPA 规范化 
minReplicas: 2
maxReplicas: 10
behavior:
  scaleDown: { stabilizationWindowSeconds: 600 }
GitOps 不再管理 replicas；HPA 是容量弹性，非高可用		 峰值扛不住 / 扩缩抖动；HPA 必须配 PDB（maxUnavailable 天然兼容） min ≥2 + 稳定窗口 + GitOps 交权
P2 ⑪+ 节点调度规范 nodeAffinity 仅 preferred；❌ 禁 nodeSelector；required 仅特殊场景 AKS 节点随升级重建变化，硬绑定会调度失败 无 nodeSelector
P2 ⑫ 集群容量 N+1 生产 ≥3 Node + 1 节点空闲余量；多 Node pool + Cluster Autoscaler；升级 --max-surge 33% 配置解决不了容量；被驱逐 Pod 必须有落位空间 节点≥3、有 N+1
P2 ⑬ startupProbe（慢启动） 
startupProbe:
  httpGet: { path: /health/live, port: 8080 }
  failureThreshold: 30
限启动 > 30s 的应用		 Java/.NET 冷启动被 liveness 误杀 → CrashLoopBackOff 慢启动应用配 startup
P2 ⑭ LimitRange 兜底 namespace 默认 requests/limits；有条件用 Gatekeeper/Kyverno 强制 防新服务漏配 requests namespace 有默认限制
P3 · 成熟度建设（季度规划 · 防止配置退化）
P3 ⑮ PriorityClass 核心 1000000 / 一般 100000 / 批处理 0 资源紧张时保核心服务不被日志采集、测试负载挤掉 核心服务已设置
P3 ⑯ 跨 AZ 与存储 StorageClass WaitForFirstConsumer；跨 AZ 用 Files/ZRS；❌ hostPath/emptyDir 存持久数据 Azure Disk 是 zonal 资源，PV 先建会锁死 Pod 到某 AZ 存储配置正确
P3 ⑰ 平台组件自身 HA CoreDNS / Ingress(AGIC) / metrics-server 多副本 + PDB + 分散 业务全配齐、Ingress 单副本照样全站中断 平台组件达标
P3 ⑱ 节点池 maxSurge 生产建议 --max-surge 33% + 计划维护窗口 升级更快，新节点先就绪、被驱逐 Pod 有落点 maxSurge 调优 + 窗口
P3 ⑲ 监控告警 disruptionsAllowed==0 持续15min（最高价值）；PDB currentHealthy==0；replicas<2；Pod Pending>5min 问题在升级当天才暴露 核心告警已上线
P3 ⑳ 季度 drain 演练 drain 单节点观察错误率；删 Pod 验证 preStop；关停一 AZ 验证容灾 配置正确 ≠ 高可用生效，演练一次性暴露所有问题 季度演练有记录
💡 执行顺序 P0PDB 修正——纯配置、零风险、当天完成，直接解除升级卡死 → P1preStop / requests / 副本 / 探针——随下次发版全量带上 → P2分布约束 / 发版 / HPA / 容量——1~2 个迭代 → P3其余按季度推进。P0+P1 完成即覆盖 90% 的实际风险。

7标准配置模板（corp-ca191-speakerapi-p · 已修复 · 直接复用）

基于实际服务 corp-ca191-speakerapi-p 修复：已补齐 P0~P2 整改项（注释标注编号），保留原命名/端口(80→443)/探针(/api/Misc/Health)。镜像 __TAG 按实际替换。

apiVersion: apps/v1
kind: Deployment
metadata:
  name: corp-ca191-speakerapi-p
  namespace: default
spec:
  replicas: 3                              # ⑥ 核心业务建议 ≥3（原 2 → 3，对外至少 ≥2）
  revisionHistoryLimit: 5
  minReadySeconds: 10                      # ⑩
  progressDeadlineSeconds: 600
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxUnavailable: 0                    # ⑩ 发版零容量损失
      maxSurge: 1                          # ⑩ 原 2 → 1，避免 2 副本集群容量翻倍
  selector:
    matchLabels:
      app: corp-ca191-speakerapi-p
  template:
    metadata:
      labels:
        app: corp-ca191-speakerapi-p
    spec:
      terminationGracePeriodSeconds: 45    # ④ 优雅下线
      topologySpreadConstraints:           # ⑨ 结果约束，替代仅靠 preferred 反亲和
        - maxSkew: 1
          topologyKey: topology.kubernetes.io/zone      # 集群启用 AZ 时才加
          whenUnsatisfiable: ScheduleAnyway
          labelSelector:
            matchLabels: { app: corp-ca191-speakerapi-p }
        - maxSkew: 1
          topologyKey: kubernetes.io/hostname
          whenUnsatisfiable: ScheduleAnyway
          labelSelector:
            matchLabels: { app: corp-ca191-speakerapi-p }
      affinity:                            # ⑨ 辅助（可选）
        podAntiAffinity:
          preferredDuringSchedulingIgnoredDuringExecution:
            - weight: 100
              podAffinityTerm:
                labelSelector:
                  matchLabels: { app: corp-ca191-speakerapi-p }
                topologyKey: kubernetes.io/hostname
      containers:
        - name: corp-ca191-speakerapi-p
          image: abbottchina.azurecr.cn/corp-ca191-nexbpm-prod/speaker-api:__TAG
          env:
            - name: ASPNETCORE_ENVIRONMENT
              value: "Prod"
            - name: ASPNETCORE_URLS
              value: "http://+:80"
          imagePullPolicy: Always
          ports:
            - containerPort: 80
          resources:                       # ⑤ 调度地基（按 P95 实际用量填）
            requests: { cpu: 200m, memory: 512Mi }
            limits:   { cpu: 1000m, memory: 512Mi }
          startupProbe:                    # ⑬ 慢启动保护
            httpGet: { path: /api/Misc/Health, port: 80 }
            failureThreshold: 30
            periodSeconds: 5
          readinessProbe:                  # ⑦
            httpGet: { path: /api/Misc/Health, port: 80 }
            initialDelaySeconds: 5
            periodSeconds: 5
            timeoutSeconds: 2
            failureThreshold: 3
          livenessProbe:                   # ⑧ 只查进程自身；确认 /api/Misc/Health 不查 DB/Redis
            httpGet: { path: /api/Misc/Health, port: 80 }
            initialDelaySeconds: 10
            periodSeconds: 10
            timeoutSeconds: 3
            failureThreshold: 6
          lifecycle:                       # ④ 优雅下线核心
            preStop:
              exec:
                command: ["/bin/sh", "-c", "sleep 15"]
---
apiVersion: policy/v1
kind: PodDisruptionBudget                  # ①②③ 新增：P0
metadata:
  name: corp-ca191-speakerapi-p-pdb
  namespace: default
spec:
  maxUnavailable: 1                        # 与 HPA 兼容；波动大用 "25%"
  unhealthyPodEvictionPolicy: AlwaysAllow
  selector:
    matchLabels: { app: corp-ca191-speakerapi-p }
---
apiVersion: v1
kind: Service
metadata:
  name: corp-ca191-speakerapi-p
  namespace: default
spec:
  selector:
    app: corp-ca191-speakerapi-p
  type: ClusterIP
  ports:
    - protocol: TCP
      port: 443
      targetPort: 80
---
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler              # ⑪（建议补配）
metadata:
  name: corp-ca191-apihpa-p
  namespace: default
spec:
  maxReplicas: 6
  minReplicas: 3                           # 与 Deployment replicas 一致
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: corp-ca191-speakerapi-p
  metrics:
    - type: Resource
      resource:
        name: cpu
        target: { type: Utilization, averageUtilization: 80 }
  behavior:                                # ⑪ 防缩容抖动
    scaleDown:
      stabilizationWindowSeconds: 600
      policies:
        - { type: Percent, value: 50, periodSeconds: 60 }
    scaleUp:
      stabilizationWindowSeconds: 0
      policies:
        - { type: Percent, value: 100, periodSeconds: 30 }

注：① 启用 HPA 后 Helm/GitOps 不再管理 spec.replicas；② 移动端 corp-ca191-speakerapi-m-p 同构，复制本模板改 app/name 即可。
