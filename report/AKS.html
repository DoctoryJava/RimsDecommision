◎AKS 高可用整改总表（按重要等级：关键 → 重要 → 增强 → 完善）

核心认知：AKS 只提供基础设施高可用，不提供应用高可用。应用高可用 = 冗余（活副本）× 流量正确性（不打给将死 Pod）× 调度可行性（被赶走的 Pod 有地方去）。业务中断 = Pod 被驱逐 + 没有冗余承接。关键+重要落实即覆盖 90% 的实际风险。

重要等级 整改项 期望配置（要点） 作用 / 不配的后果 验收标准
🔴 关键（决定高可用能否成立）
关键 ⑯ 跨可用区（AZ）冗余 节点池跨多个可用区(AZ)；多副本分布到不同 AZ；topologySpreadConstraints 加 zone 级约束 单 AZ 故障 = 该区全部节点/副本同时宕机；跨 AZ 才真正确保"单点故障不断服" 节点跨 ≥2 AZ；副本分布到不同 AZ
关键 ⑥ replicas ≥ 2（核心≥3） 对外 ≥2；核心 ≥3；有状态 ≥3；仅 quorum 类组件（etcd/ZooKeeper/Redis Sentinel/Kafka Controller）才需奇数
用 kubectl get pod -o wide 验证实际分散		 单副本 = 升级必然中断；同节点多副本 = 假冗余（CA072 实证） replicas 达标且实际跨节点
关键 ⑫ 集群容量 N+1 生产 ≥3 Node + 1 节点空闲余量；多 Node pool + Cluster Autoscaler；升级 --max-surge 33% 配置解决不了容量；被驱逐 Pod 必须有落位空间 节点≥3、有 N+1
关键 ⑨ topologySpread 分布约束 
topologySpreadConstraints:
  - maxSkew: 1
    topologyKey: kubernetes.io/hostname
    whenUnsatisfiable: DoNotSchedule   # 核心服务（前提：⑫容量N+1达标）
hostname 级核心服务用 DoNotSchedule（前提：⑫容量 N+1 已达标）；zone 级保留 ScheduleAnyway 防止跨 AZ 节点不足 Pending		 结果约束，Pod 均匀分布；preferred 反亲和会被稀释（CA072） spread 已配置且实际分散；若用 DoNotSchedule，需先确认 ⑫ 节点容量 N+1 达标
关键 ⑰ 平台组件自身 HA CoreDNS / Ingress(AGIC) / metrics-server 多副本 + PDB + 分散 业务全配齐、Ingress 单副本照样全站中断 平台组件达标
🟠 重要（决定升级/发版是否中断）
重要 ① PDB 统一用 maxUnavailable
禁 minAvailable（绝对值）+ HPA 组合（百分比可用，但需校验）		 
maxUnavailable: 1
unhealthyPodEvictionPolicy: AlwaysAllow
selector:
  matchLabels: { app: <svc> }
HPA 波动大用 "25%"（向上取整）
❌ minAvailable 绝对值 + HPA 缩容 → disruptionsAllowed=0		 防止维护期一次驱逐全部 Pod。
不配：被一次驱逐 / 配错则节点升级永久卡死		 PDB 全用 maxUnavailable；disruptionsAllowed ≥ 1
重要 ② 消除 disruptionsAllowed==0 稳态 ALLOWED ≥ 1；用一条命令排查：kubectl get pdb -A ALLOWED=0 会 drain 永久阻塞，升级超时失败。现象误导：Pod 全 Running、健康全绿但升级失败 全集群 PDB ALLOWED ≥ 1
重要 ③ PDB selector 命中 / 单副本 / 重叠 selector 必须与 Pod 标签完全一致；单副本不配 PDB；禁止多 PDB 命中同组 Pod 不命中 = 保护形同虚设；单副本+PDB = 锁死驱逐；多 PDB = Eviction 直接失败 currentHealthy == 实际副本数
重要 ④ 优雅下线
preStop + terminationGracePeriod		 
terminationGracePeriodSeconds: 45
lifecycle:
  preStop:
    exec: { command: ["/bin/sh","-c","sleep 15"] }
AGIC 场景 15~30s；应用处理 SIGTERM		 SIGTERM 与摘流并行无顺序；preStop 等摘除传播。不配：升级/发版必现 502 对外服务均有 preStop，drain 演练无 502
重要 ⑦ readinessProbe 规范 
readinessProbe:
  httpGet: { path: /health/ready, port: 8080 }
  periodSeconds: 5
  failureThreshold: 3
端点真实反映能否处理请求		 防止未就绪切入流量。不配：请求打到未就绪 Pod readiness 已配置且真实
重要 ⑧ liveness 禁查外部依赖 liveness 只查进程自身；❌ 不查 DB/Redis/下游 查外部依赖 → 依赖抖动 → 全副本重启 → 级联雪崩 liveness 不查外部依赖
🔵 增强（生产质量）
增强 ⑤ resources.requests 全量 
requests: { cpu: 200m, memory: 512Mi }
limits:   { cpu: 1000m, memory: 512Mi }
memory.limits == requests		 调度地基：驱逐后 Pod 才有落点；QoS 决定驱逐顺序。不配：驱逐后 Pending、HPA 指标失真 所有容器有 requests
增强 ⑩ 发版策略 maxUnavailable:0 
rollingUpdate:
  maxUnavailable: 0
  maxSurge: 1
minReadySeconds: 10
 发版先起新再停旧，零容量损失；PDB 对发版不生效，由 rollingUpdate 管 对外服务 rollingUpdate=0
增强 ⑪ HPA 规范化 
minReplicas: 2
maxReplicas: 10
behavior:
  scaleDown: { stabilizationWindowSeconds: 600 }
GitOps 不再管理 replicas；HPA 是容量弹性，非高可用		 峰值扛不住 / 扩缩抖动；HPA 必须配 PDB（maxUnavailable 天然兼容） min ≥2 + 稳定窗口 + GitOps 交权
增强 ⑬ startupProbe（慢启动） 
startupProbe:
  httpGet: { path: /health/live, port: 8080 }
  failureThreshold: 30
限启动 > 30s 的应用		 Java/.NET 冷启动被 liveness 误杀 → CrashLoopBackOff 慢启动应用配 startup
增强 ⑭ LimitRange 兜底 namespace 默认 requests/limits；有条件用 Gatekeeper/Kyverno 强制 防新服务漏配 requests namespace 有默认限制
🟢 完善（长期保障）
完善 ⑮ PriorityClass 核心 1000000 / 一般 100000 / 批处理 0 资源紧张时保核心服务不被日志采集、测试负载挤掉 核心服务已设置
完善 ⑱ 节点池 maxSurge 生产建议 --max-surge 33% + 计划维护窗口 升级更快，新节点先就绪、被驱逐 Pod 有落点 maxSurge 调优 + 窗口
完善 ⑲ 监控告警 disruptionsAllowed==0 持续15min（最高价值）；PDB currentHealthy==0；replicas<2；Pod Pending>5min 问题在升级当天才暴露 核心告警已上线
完善 ⑳ 季度 drain 演练 drain 单节点观察错误率；删 Pod 验证 preStop；关停一 AZ 验证容灾 配置正确 ≠ 高可用生效，演练一次性暴露所有问题 季度演练有记录
💡 重要等级说明（按对高可用的关键程度，非执行时机）
关键跨 AZ/副本数/容量/分布/平台组件——决定高可用能否成立，架构层面必须落实 → 重要PDB/优雅下线/探针——决定升级发版是否中断 → 增强resources/发版策略/HPA——提升生产质量 → 完善监控/演练/优先级——长期保障防退化。关键+重要落实即覆盖 90% 的实际风险。

7标准配置模板（corp-ca191-speakerapi-p · 已修复 · 直接复用）

基于实际服务 corp-ca191-speakerapi-p 修复：已补齐 P0~P2 整改项（注释标注编号），保留原命名/端口(80→443)/探针(/api/Misc/Health)。镜像 __TAG 按实际替换。

apiVersion: apps/v1
kind: Deployment
metadata:
  name: corp-ca191-speakerapi-p
  namespace: default
spec:
  replicas: 3                              # ⑥ 核心业务建议 ≥3（原 2 → 3，对外至少 ≥2）
  revisionHistoryLimit: 5
  minReadySeconds: 10                      # ⑩
  progressDeadlineSeconds: 600
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxUnavailable: 0                    # ⑩ 发版零容量损失
      maxSurge: 1                          # ⑩ 原 2 → 1，避免 2 副本集群容量翻倍
  selector:
    matchLabels:
      app: corp-ca191-speakerapi-p
  template:
    metadata:
      labels:
        app: corp-ca191-speakerapi-p
    spec:
      terminationGracePeriodSeconds: 45    # ④ 优雅下线
      topologySpreadConstraints:           # ⑨ 结果约束，替代仅靠 preferred 反亲和
        - maxSkew: 1
          topologyKey: topology.kubernetes.io/zone      # 集群启用 AZ 时才加
          whenUnsatisfiable: ScheduleAnyway
          labelSelector:
            matchLabels: { app: corp-ca191-speakerapi-p }
        - maxSkew: 1
          topologyKey: kubernetes.io/hostname
          whenUnsatisfiable: DoNotSchedule   # ⑨ 核心服务硬约束（前提：⑫容量N+1达标）
          labelSelector:
            matchLabels: { app: corp-ca191-speakerapi-p }
      affinity:                            # ⑨ 辅助（可选）
        podAntiAffinity:
          preferredDuringSchedulingIgnoredDuringExecution:
            - weight: 100
              podAffinityTerm:
                labelSelector:
                  matchLabels: { app: corp-ca191-speakerapi-p }
                topologyKey: kubernetes.io/hostname
      containers:
        - name: corp-ca191-speakerapi-p
          image: abbottchina.azurecr.cn/corp-ca191-nexbpm-prod/speaker-api:__TAG
          env:
            - name: ASPNETCORE_ENVIRONMENT
              value: "Prod"
            - name: ASPNETCORE_URLS
              value: "http://+:80"
          imagePullPolicy: Always
          ports:
            - containerPort: 80
          resources:                       # ⑤ 调度地基（按 P95 实际用量填）
            requests: { cpu: 200m, memory: 512Mi }
            limits:   { cpu: 1000m, memory: 512Mi }
          startupProbe:                    # ⑬ 慢启动保护
            httpGet: { path: /api/Misc/Health, port: 80 }
            failureThreshold: 30
            periodSeconds: 5
          readinessProbe:                  # ⑦
            httpGet: { path: /api/Misc/Health, port: 80 }
            initialDelaySeconds: 5
            periodSeconds: 5
            timeoutSeconds: 2
            failureThreshold: 3
          livenessProbe:                   # ⑧ ⚠️高风险：上线前必须代码走查，见下方专项说明
            httpGet: { path: /api/Misc/Health, port: 80 }
            initialDelaySeconds: 10
            periodSeconds: 10
            timeoutSeconds: 3
            failureThreshold: 6
          lifecycle:                       # ④ 优雅下线核心
            preStop:
              exec:
                command: ["/bin/sh", "-c", "sleep 15"]
---
apiVersion: policy/v1
kind: PodDisruptionBudget                  # ①②③ 新增：P0
metadata:
  name: corp-ca191-speakerapi-p-pdb
  namespace: default
spec:
  maxUnavailable: 1                        # 与 HPA 兼容；波动大用 "25%"
  unhealthyPodEvictionPolicy: AlwaysAllow
  selector:
    matchLabels: { app: corp-ca191-speakerapi-p }
---
apiVersion: v1
kind: Service
metadata:
  name: corp-ca191-speakerapi-p
  namespace: default
spec:
  selector:
    app: corp-ca191-speakerapi-p
  type: ClusterIP
  ports:
    - protocol: TCP
      port: 443
      targetPort: 80
---
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler              # ⑪（建议补配）
metadata:
  name: corp-ca191-apihpa-p
  namespace: default
spec:
  maxReplicas: 6                        # 🔧示例值，需按该服务实际 P95 压测后确定，不可直接复用
  minReplicas: 3                           # 与 Deployment replicas 一致
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: corp-ca191-speakerapi-p
  metrics:
    - type: Resource
      resource:
        name: cpu
        target: { type: Utilization, averageUtilization: 80 }
  behavior:                                # ⑪ 防缩容抖动
    scaleDown:
      stabilizationWindowSeconds: 600
      policies:
        - { type: Percent, value: 50, periodSeconds: 60 }
    scaleUp:
      stabilizationWindowSeconds: 0
      policies:
        - { type: Percent, value: 100, periodSeconds: 30 }

注：① 启用 HPA 后 Helm/GitOps 不再管理 spec.replicas；② 移动端 corp-ca191-speakerapi-m-p 同构，复制本模板改 app/name 即可。

⚠️ 高风险修订专项说明：liveness/readiness 共用端点问题 模板中 startupProbe / readinessProbe / livenessProbe 均指向同一个 /api/Misc/Health 端点。P1⑧ 要求 liveness 不能查外部依赖，但该端点的具体实现未经代码验证——若内部检测了 DB/Redis 连接（常见于 .NET AddHealthChecks() 默认写法），依赖一抖动会导致全部副本同时 liveness 失败 → 同时重启 → 级联雪崩，正是 ⑧（重要级）要防的最坏场景。
上线前必须完成（阻断项，不可跳过）：① 由开发提供 /api/Misc/Health 源码实现，确认是否含外部依赖检查；② 若含依赖检查，必须拆分为 /health/live（仅进程存活）与 /health/ready（含依赖），liveness/startup 指向前者、readiness 指向后者；③ 若确认不含，书面记录存档备查，而非仅凭注释。此项优先级等同 P1，应单列为发版 checklist 强制项。
