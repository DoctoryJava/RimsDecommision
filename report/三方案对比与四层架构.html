2.1Appsmith 低代码：优点与缺点

方案 A 的前端选型 —— "快"是真的快，"省"未必真的省。

✔ 优点

  • 拖拽建页、交付最快：首期约 1 个月即可上线
  • 实施门槛最低：无需前端研发能力，业务人员亦可参与
  • 技术栈成熟、社区活跃，团队易接手
  • 自带用户/角色管理，简单场景下免开发
  • Business 档授权费低（已计入 TCO）

✘ 缺点

  • 逐系统建页：15 个系统逐个拖拽，规模上并不省人天（边际 8~12.9 人天/系统，高于配置化平台的 3.5~8）
  • 若直连 Databricks：UC 列掩码与统一审计双双失效，合规兜不住
  • RBAC 与 PG RLS 两套权限体系并行维护，易"页面藏了但接口没拦"
  • SSO 需 Enterprise 版，$2,500/月保底，与数据量无关的刚性支出（TCO ¥121→¥168 万）
  • 复杂查询/导出/下钻等定制需求仍要写 JS 片段，低代码逐渐变"低效代码"
一句话：Appsmith 适合"少量系统 + 快速上线 + 无合规硬约束"的场景；15 系统规模 + 个人信息合规要求下，自研配置化平台（B/B2）一次研发、处处复用，长期更省。

湖仓的结构特征：存储极便宜、算力另付。A 的胜负手不是系统数，而是 PG 热数据是否进入 10~16 TB 安全区。

存储单价（Azure 列表价）：Blob Hot ¥131 / Cool ¥73 / Cold ¥33 每 TB·月。B/B2 湖存需在线可查走 Hot/Cool 混合，故单价高于 A 的 Cool→Cold 冷存，但总量口径下存储费不到 A 的一半。

怎么读这些数字

  • ① 存算分离的红利：B/B2 存储仅 ¥0.18~0.30 万/月（不到 A 的一半），20 TB 全量在线可查；A 为压成本只能把 90% 数据沉为不可查的冷文件。
  • ② 算力按需 vs 常驻：B/B2 读侧 ¥0.59~0.89 万/月按用量浮动；B2 空闲缩 0，比 B 再省约 ¥0.3 万/月。
  • ③ 人天是一次性、月费是累加：A 建设期人天最少，但每系统仍需 8~12.9 人天逐个建页；A vs B2 的建设人天交叉点在 N≈17 个系统 —— 15 系统规模已贴线，此后 B2 反超且越走越省。
  • ④ A 的隐藏天花板：PG 单实例 32 TiB 上限，扣除索引与膨胀安全区 15~20 TB；热数据进入 10~16 TB 后实例费陡增，超过即被迫拆库或转 B/B2。
3 年 TCO 口径：含建设人天折算 + 云资源 + 授权；不含跨区流量、备份溢价、企业折扣与专职人力运维。若计入自建 Trino 的运维人力，B 与 B2 差距进一步拉大。

3四层应用架构（宏观视图）

自上而下四层：用户看到什么（UI）、业务做什么（Service）、怎么读写数据（Data Access）、数据放在哪（Storage）。每个组件附一句话解释。

表现层

UI LAYER

用户唯一入口：元数据驱动的配置化前端，新系统接入零代码。

配置化查询平台（React）按元数据动态渲染查询表单、结果表格与明细页，不逐系统开发页面
附件预览 / 下载后端签发 SAS 令牌后前端直连 Blob 流式取件，不占服务带宽
报表与导出查询结果导出 CSV/Excel，供审计与离线分析
统一登录（Entra ID SSO）OIDC 单点登录，角色决定可见系统与页面
HTTPS 443 · REST/JSON · JWT

业务服务层

SERVICE LAYER

.NET 10 单体服务（AKS 容器化）：全部业务规则与调度在此收敛。

认证与权限服务校验 JWT、按"用户→系统→表"元数据判定可访问范围（导航层闸门）
元数据管理系统台账、源库/表清单、勾选配置、保留期策略的增删改查
查询代理拼装并校验 SQL（表名白名单）、限流、超时控制、结果裁剪
附件服务附件索引检索、SAS 签发、SHA-256 台账核对
生命周期 / 销毁调度到期扫描、触发 Databricks 销毁作业、结果回写台账
审计与通知操作留痕上报 App Insights，到期/审批消息推送
私有端点 · 托管标识免密

数据访问层

DATA ACCESS LAYER

数据"怎么进、怎么查、怎么治理"：编排、抽取、引擎与治理平面。

编排：Azure Data Factory定时/事件触发抽取与销毁作业，薄触发层 + 失败重试
抽取：SeaTunnel200+ 连接器批量抽取源库选中表，写入 RAW 层
计算：Databricks ServerlessJobs 承担 ETL/压缩/销毁；SQL Warehouse 承担在线查询（空闲缩 0）
治理：Unity Catalog表/行/列授权、列掩码、血缘与审计 —— 真正的权限闸门
凭据：Key Vault源库连接串、DEK/KEK 密钥集中托管，应用免密访问
ABFS · JDBC/ODBC · 私有端点

存储层

STORAGE LAYER

存算分离：对象存储承载全量归档，元数据库只存配置与权限。

ADLS Gen2 · Iceberg 湖结构化归档数据，RAW→CURATED→LAKE→SERVE 四层，PB 级容量
Blob · 附件账户非结构化附件独立账户（FNS），Cool→Cold 自动降档，WORM 可选
Azure SQL · 元数据库系统台账、表清单、查询配置、保留策略、审计索引（35 张表）
监控与日志App Insights + Azure Monitor：指标、告警、审计流水留存
读图要点：权限的"真闸门"在数据访问层（UC 授权/掩码），Service 层的校验是导航与体验层；业务数据永不进入元数据库，全部驻留存储层的湖仓。
