退役归档平台 · 三方案对比 与 四层应用架构

方案 A：PG 合一群 + Appsmith 低代码　|　方案 B：湖仓一体 + Databricks写 + 配置化平台（Trino 读）　|　方案 B2：湖仓一体 + Databricks 读写

1三方案速览

方案 A

PG 合一群 + Appsmith 低代码

  • 交付最快：首期约 1 个月
  • 拖拽建页，实施门槛最低
  • 技术栈成熟，团队易接手
  • SSO 须升级企业版授权（刚性支出、与用量无关），投入最高而能力最弱
  • 每系统 100 张表仅 10 张入库，90 张沦为"死数据"不可 SQL 查询
  • 无跨系统联邦，监管抽查需人工还原
  • 单库上限 32 TiB；热数据进入 10~16 TB 后实例费陡增
  • PG 索引维护成本大：大表索引重建 / 膨胀治理（VACUUM）持续吃实例资源与维护窗口
  • SQL 查询随数据量变慢：单实例无分布式算力，跨年检索 / 复杂聚合越查越慢，只能纵向加规格
  • 数据销毁无证明：PG DROP / TRUNCATE 无销毁痕迹，监管抽查无法出具"已合规销毁"证书
方案 B

湖仓一体 + 配置化平台（Trino 读）

  • 引擎中立，不绑定单一厂商
  • 全量数据（100 张表）可查
  • 超大规模（>120 TB）场景下相对更优
  • 需自建并运维 Trino 集群
  • 列级脱敏能力不可用（需明文/脱敏双份数据）
  • 读侧常驻集群，长期投入高于 B2
  • 销毁依赖 Iceberg tombstone 软删除，需自建流程出具销毁证明，WORM 需额外配置
方案 B2

湖仓一体 + Databricks 读写

★ 推荐
  • 能力全面胜出，长期投入最优
  • 全量可查 + 跨系统联邦 + 统一审计溯源
  • 零集群运维，空闲自动停机
  • 新系统接入零代码，规模越大越省
  • 首期约 3 个月建平台
  • 治理层绑定 Unity Catalog（数据仍为开放 Iceberg）
  • Databricks 销毁作业自动执行 + 台账回写，开箱即出具"已销毁"记录

2三个方案的核心区别

一张表看清 A / B / B2 在九个维度上的差异。

维度A · PG + AppsmithB · 湖仓 + TrinoB2 · 湖仓 + Databricks ★
前端Appsmith 拖拽（每系统逐个建页）自研配置化查询平台（元数据驱动，零代码接入）同 B（B/B2 前端完全相同）
数据库/查询引擎PostgreSQL 合库（查询算力含在实例内；索引与膨胀治理另计维护成本）ADLS + Iceberg；Trino 自建集群读ADLS + Iceberg；Databricks Serverless 读写
数据可查性10%（10/100 张表），冷数据仅文件留存100% 全量 SQL 可查100% 全量 SQL 可查 + 跨系统联邦
权限模型Appsmith RBAC 与 PG RLS 两套体系并行rules.json 表级授权 + 查询代理鉴权Unity Catalog：表/行/列级，GRANT 向下继承，任何访问路径强制生效
字段级加密/脱敏无 TDE；应用层加密后字段不可检索、不可排序脱敏表不可读，须维护明文+脱敏双份数据原生列掩码：一次配置全局生效，有权限见明文、无权限见掩码
密钥轮转代价高：换密钥需重刷全部历史数据信封加密，只重包装密钥同左
运维负担PG + Blob + Appsmith，另扛索引重建 / VACUUM / 慢查询调优（最重）最重：+ Trino 集群部署/升级/HA/容量零集群运维，Serverless 空闲缩 0
审计举证部分：pgaudit 与应用日志需人工关联需自建审计组件开箱即用：谁·何时·查了什么，一条命令导出
查询性能与扩展单实例纵向扩展：复杂分析查询随数据量增长显著变慢；索引重建 / VACUUM 维护重MPP 分布式并行，PB 级从容弹性并行 + SERVE 物化加速，首屏 2~5 s
数据销毁合规性无证明：PG DROP / TRUNCATE 无销毁痕迹，监管抽查无法出具"已合规销毁"证书需自建：Iceberg tombstone 软删除，需自建流程出具销毁证明，WORM 需额外配置开箱即用：Databricks 销毁作业自动执行 + 台账回写，Unity Catalog 审计追踪，一条命令导出销毁记录

2.1前端选型对比：Appsmith 低代码 vs 自研配置化平台

方案 A 用 Appsmith 拖拽建页；方案 B / B2 自研元数据驱动的配置化平台。本质差异："逐系统建页" vs "一次研发、处处复用"。

维度Appsmith 低代码（方案 A）自研配置化平台（方案 B / B2）★
建页方式逐系统拖拽建页，每个系统重复一遍元数据驱动：按"表清单 + 查询配置"动态渲染，平台只建一次
新系统接入重新拖拽页面，边际投入是三方案中最高的一档零代码：勾选表、配置字段即生成查询页
页面一致性多系统各建各的，风格与交互易漂移全平台统一，升级一处全局生效
权限模型两套体系：Appsmith RBAC 与数据库权限并行维护，易"页面藏了、接口没拦"一套体系：后端校验（导航）+ 引擎授权（真闸门），任何路径强制生效
与 Databricks / UC 集成直连失效：绕过 UC 列掩码与统一审计查询代理 + UC 原生集成，掩码 / 审计全生效
SSO / SCIM需升级 Enterprise 授权（刚性支出、与用量无关）自研对接 Entra ID（OIDC），无额外授权
定制能力复杂逻辑退化为写 JS 片段，越写越难维护完全掌控：下钻 / 导出 / 附件预览 / 脱敏展示自由实现
团队要求无需前端研发能力，业务人员可参与需 React 前端研发（已含在 B / B2 建设人力中）
首期交付最快约 1 个月约 2 个月（此后新系统边际趋近于零）
适用场景系统少、快速上线、无个人信息合规硬约束≥15 系统、有合规要求、长期运营
一句话：Appsmith 赢在"第一个系统上线快"；自研配置化赢在"第 N 个系统零代码接入"—— 系统越多、合规要求越高，自研优势越大。

2.2查询引擎：Databricks Serverless vs 自建 Trino

B 与 B2 的唯一差异就在读侧引擎 —— 也是 B2 胜出的关键。

维度Trino（方案 B）Databricks Serverless（方案 B2）★
运维自建集群：部署 / 升级 / HA / 容量调优全自己来零运维：托管运行，故障自动重建
付费模式常驻小集群 —— 没人查也要付费按秒计费 + 空闲自动缩 0，低频归档查询天然适配
并发突发小集群排队，审计批量取证慢自动横向扩缩，突发并发无感
权限/治理rules.json 表级授权（三级显式配置）Unity Catalog：表/行/列级 + 血缘 + 审计开箱即用
列级脱敏完全不可用：带掩码的表直接报错（fail closed），需维护双份数据COLUMN MASK 原生生效，任何客户端绕不过
网络接入VNet 注入（host + container 双子网）NCC + 托管私有端点（新建工作区默认即 Premium 档）
节点间加密默认不加密，需显式配置 internal TLS（易踩坑）平台内部链路默认加密
引擎中立开放引擎，无厂商绑定绑定 Databricks —— 但存储是开放 Iceberg，数据可随时迁走

3四层应用架构（宏观视图）

自上而下四层：用户看到什么（UI）、业务做什么（Service）、怎么读写数据（Data Access）、数据放在哪（Storage）。每个组件附一句话解释。

表现层

UI LAYER

用户唯一入口：元数据驱动的配置化前端，新系统接入零代码。

配置化查询平台（React）按元数据动态渲染查询表单、结果表格与明细页，不逐系统开发页面
附件预览 / 下载后端签发 SAS 令牌后前端直连 Blob 流式取件，不占服务带宽
报表与导出查询结果导出 CSV/Excel，供审计与离线分析
统一登录（Entra ID SSO）OIDC 单点登录，角色决定可见系统与页面
HTTPS 443 · REST/JSON · JWT

业务服务层

SERVICE LAYER

.NET 10 单体服务（AKS 容器化）：全部业务规则与调度在此收敛。

认证与权限服务校验 JWT、按"用户→系统→表"元数据判定可访问范围（导航层闸门）
元数据管理系统台账、源库/表清单、勾选配置、保留期策略的增删改查
查询代理拼装并校验 SQL（表名白名单）、限流、超时控制、结果裁剪
附件服务附件索引检索、SAS 签发、SHA-256 台账核对
生命周期 / 销毁调度到期扫描、触发 Databricks 销毁作业、结果回写台账
审计与通知操作留痕上报 App Insights，到期/审批消息推送
私有端点 · 托管标识免密

数据访问层

DATA ACCESS LAYER

数据"怎么进、怎么查、怎么治理"：编排、抽取、引擎与治理平面。

编排：Azure Data Factory定时/事件触发抽取与销毁作业，薄触发层 + 失败重试
抽取：SeaTunnel200+ 连接器批量抽取源库选中表，写入 RAW 层
计算：Databricks ServerlessJobs 承担 ETL/压缩/销毁；SQL Warehouse 承担在线查询（空闲缩 0）
治理：Unity Catalog表/行/列授权、列掩码、血缘与审计 —— 真正的权限闸门
凭据：Key Vault源库连接串、DEK/KEK 密钥集中托管，应用免密访问
ABFS · JDBC/ODBC · 私有端点

存储层

STORAGE LAYER

存算分离：对象存储承载全量归档，元数据库只存配置与权限。

ADLS Gen2 · Iceberg 湖结构化归档数据，RAW→CURATED→LAKE→SERVE 四层，PB 级容量
Blob · 附件账户非结构化附件独立账户（FNS），Cool→Cold 自动降档，WORM 可选
Azure SQL · 元数据库系统台账、表清单、查询配置、保留策略、审计索引（35 张表）
监控与日志App Insights + Azure Monitor：指标、告警、审计流水留存
读图要点：权限的"真闸门"在数据访问层（UC 授权/掩码），Service 层的校验是导航与体验层；业务数据永不进入元数据库，全部驻留存储层的湖仓。
